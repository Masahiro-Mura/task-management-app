# TaskFlow 改修計画

最終更新: 2026-11-05(フェーズ4完了)

## 設計思想（判断の基準）

すべての改修はこの5つに照らして入れるかどうかを決める。

1. **開いた瞬間に"今やる1つ"が分かる。** 一覧を眺めさせない。
2. **推薦には必ず理由がある。** 理由を説明できない判断はロジックに入れない。
3. **現実的な1日。** 空き時間に入らないものは隠さず、正直に示す。
4. **罪悪感を生まない。** 期限切れや溜まったタスクで責めない。
5. **着手しやすさとシンプルさ。** 大きいタスクは小さくする。機能は足しすぎない。

## 現状と思想のずれ

| 思想 | 今のコード | ずれ |
|---|---|---|
| 1. 今やる1つ | `DecisionEngine` が1件だけ選び、ホームに表示する | 時間が経っても再計算されない。タスク0件のとき空状態が2つ重なって出る |
| 2. 理由 | `makeReason` が条件を並べる | 「なぜ他ではなくこれか」が説明されない。「〜ため、〜ため、〜ためです」と不自然な文になる |
| 3. 現実的な1日 | 空き時間が `availableMinutes = 45` に固定されている | ユーザーの実際の空き時間が反映されない。入るタスクがないと「実行できるタスクがありません」とだけ出て、何が入らないのか分からない |
| 4. 罪悪感なし | 期限切れの理由文は「期限を過ぎている」 | 期限切れで責める表現になっている。今日/明日の欄に期限切れ・未予定のタスクが出ず、見えないまま溜まる |
| 5. 着手しやすさ | `prerequisiteIDs` はモデルにある | 設定するUIがない。大きいタスクを分解する手段がない |
| — | `priority` を追加した | `DecisionEngine` の並び替えで使われていない |

## 既知の不具合（思想以前の土台）

コードを読んで見つかったもの。上の2つはユーザーのデータに関わるので最優先で直す。

1. **データ消失の危険がある。** `loadTasks()` は `try?` で読み込むため、読み込みに失敗すると `nil` になる。すると `init` がサンプルタスクを読み込み、次に何か操作したときの `saveTasks()` で保存データが上書きされる。将来モデルを変えて読み込みが失敗した場合に、全タスクが消える。
2. **削除したタスクを前提にしていたタスクが、二度と推薦されない。** 削除されたIDは完了済みIDに含まれないため、`isExecutable` が常に `false` になる。
3. **ゴミ箱ボタンが何もしない。** `TaskRowView` のゴミ箱ボタンはどの画面でも `onDelete` を渡されておらず、押しても何も起きない。
4. **空状態が2つ表示される。** タスクが0件のとき「まだタスクがありません」と `ContentUnavailableView` が両方出る。
5. **初回起動時に開発用のサンプルタスクが入る。** リリース前には外す必要がある。

## 段階的な計画

各フェーズは「ロジックはまず `TaskFlowTests` にテストを書いてから直す」「1フェーズ＝数コミット、ブランチを切って main にマージ」で進める。

### フェーズ0：土台を固める（データ安全性とテスト）

ねらい：これ以降の改修でユーザーのデータを壊さない状態にする。

- [x] 読み込み失敗とデータなしを区別する。失敗時はサンプルで上書きせず、元データを別キーに退避する（不具合1）
- [x] 推薦時、存在しない前提IDは「満たされている」とみなす。あわせて削除時に他タスクの `prerequisiteIDs` から取り除く（不具合2）
- [x] `TaskRowView` のゴミ箱ボタンを外す。削除は一覧のスワイプ＋確認に一本化する（不具合3、シンプルさ優先）
- [x] タスク0件時の空状態を1つにまとめる（不具合4）
- [x] サンプルタスクは `#if DEBUG` に限定する（不具合5）
- [x] `DecisionEngine` のテストを追加する：前提未完了、時間超過、期限切れ、期限なし同士、全件完了、空配列

完了条件：上記テストがすべて通り、既存の保存データがそのまま読める。

### フェーズ1：核の「今やる1つ」を正しくする

ねらい：思想1〜3。推薦がユーザーの今の状況を反映し、理由が納得できるものにする。

- [x] **空き時間を指定できるようにする。** ホームの推薦カードの上に「15 / 30 / 45 / 60 / 90分」の選択肢を置き、選んだ値を `UserDefaults` に保存する。入力欄ではなく選択肢にして、開いてすぐ選べるようにする
- [x] **並び替えに優先度を入れる。** 「期限が24時間以内のもの（期限切れを含む。同士は期限が早い順）→ 優先度 → 期限 → 所要時間の短さ」。どれを効かせたかは理由文に出す
- [x] **理由文を作り直す。** 条件を全部並べるのではなく、決め手を1〜2個だけ自然な文にする。例：「期限が今日で、30分の空き時間に収まるからです。」決め手の判定は `DecisionEngine` が返し、文章化をテストで固定する
- [x] **時間経過で再計算する。** アプリが前面に戻ったとき（`scenePhase`）と、表示中は一定間隔で `updateRecommendation()` を呼ぶ
- [x] **入らないものを正直に示す。** 候補がないときは、理由を区別して出す：「空き時間に収まらないタスクが3件（最短60分）」「前提待ちが2件」「すべて完了」。次の一手として、収まる空き時間の選択肢があればそこへ切り替えるボタンを添える（「分解する」はフェーズ3）

完了条件：空き時間を変えると推薦が変わり、推薦なしの理由がテストで区別できる。

### フェーズ2：現実的な1日と、罪悪感を生まない表示

ねらい：思想3・4。溜まったタスクが見えなくなったり、責める表示になったりしないようにする。

- [x] **今日の欄を広げる。** 予定日が今日のものに加え、期限が今日のものと、予定日や期限を過ぎた未完了タスクを「持ち越し」として含める。赤字や「期限切れ」の強調はせず、行に小さく「持ち越し」と添えるだけにする。明日の欄には、今日の欄に出るものを重ねて出さない
- [x] **期限切れの理由文を穏やかにする。** 「期限は過ぎていますが、所要時間30分が空き時間45分に収まるので、今なら片づけられます。」にした。期限を過ぎた日数によらず同じ文（「少し」は付けない）
- [x] **放置タスクの冬眠。** 14日間触っていない未完了タスクを「冬眠中」として推薦と今日・明日の欄から外し、「すべてのタスク」で右スワイプ「起こす」で戻せるようにする。追加・編集・完了切り替え・起こすで触れた日時（`updatedAt`）を更新する。既存データは読み込み時刻から数える
  - 期限があるタスクと、予定日が今日以降のタスクは冬眠させない（約束した日付を見えなくしないため）
  - 冬眠中のタスクも、前提タスクとしては未完了のまま扱う
  - 推薦がないときのカードに「冬眠中のタスクが◯件」と出す

完了条件：期限切れのタスクが責める表示なしで今日の欄に見え、冬眠の判定がテストで確認できる。

### フェーズ3：着手しやすさ

ねらい：思想5。大きいタスクで止まらないようにする。

- [x] **前提タスクを設定するUI。** 編集画面に「先に終わらせるタスク」の選択を追加する。自分自身と、循環する組み合わせ（このタスクを直接・間接に前提にしているもの）は候補に出さない。完了済みのタスクは、すでに選ばれているものだけ残す
- [x] **分解する。** 編集画面の「小さく分ける」から、2〜5個に分ける（初期値は所要時間を等分して5分単位に切り上げ）。新しい仕組みは作らず、既存の `prerequisiteIDs` を使う
  - 計画では「元タスクの前提として順番につなぐ」としていたが、元タスクを残すと空き時間に入らないまま一覧に残るため、**元タスクを分けたタスクの列に置き換える**ことにした
  - 1つ目は元タスクの前提を引き継ぎ、以降は前のものを前提にする。元タスクを前提にしていたタスクは、最後の1つを前提にする
  - 優先度・予定日・期限は、すべての部分に引き継ぐ
  - 推薦がないときのカードで、空き時間に収まらないタスクがあれば「小さく分けられます」と案内する

完了条件：90分のタスクを3つに分けると、45分の空き時間で最初の1つが推薦される。

### フェーズ4：ホームのUX（推薦カードで行動まで完結させる）

ねらい：思想1・5。開いて「今やる1つ」が分かるだけでなく、その場で取りかかれるようにする。画面の大半を推薦カードにして、一覧の要素は控えめにする。

- [x] **推薦カードに操作を付ける。**
  - 「始める」：集中画面に切り替える。タスク名・経過時間・目安の時間・「完了」だけを出す。目安を過ぎても責める表示はしない
  - 「完了」：すぐ次の推薦に切り替え、数秒間「元に戻す」を出す
  - 「今はやらない」：そのタスクを1時間だけ推薦から外し、次の候補を出す。理由は聞かない。冬眠の数え（`updatedAt`）には影響させない。推薦がないときのカードで件数を示し、取り消せるようにする
- [x] **一覧の要素を減らす。** 今日の欄は「今日 ◯件（持ち越し ◯）」の1行に畳み、タップで開く。明日の欄はホームから外し、「すべてのタスク」の行に「明日」と添える。「すべてのタスク」はツールバーのアイコンに移す。登録タスク数の表示は消す
- [x] **1行で追加する。** 画面下に入力欄を常に置く。「請求書を送る 15分」「資料を読む 1時間」のように書くと時間を読み取る（全角数字も可）。時間がなければ30分。詳しく入れる画面は「＋」に残す
- [x] **細かい点。** ホームの今日の行をタップで編集画面に行ける。推薦が変わるときはカードの中身だけを切り替える
- 空き時間の選び方は、1回のタップで変えられる今の5つ並びを残す
- 今日の欄の件数は、完了したものを除いた「残り」を示す。全部終わったら「今日の分は終わりました」
- 集中画面はアプリを終了すると閉じる（経過時間は保存しない）。ロック画面やダイナミックアイランドへの表示（ライブアクティビティ）は今後の候補

完了条件：推薦カードから完了・今はやらない・始めるができ、1行入力で時間つきのタスクを追加できる。

## やらないこと（当面）

- MCP/AIエージェント連携
- 通知・リマインダー、カレンダー連携、iCloud同期
- タグ・プロジェクト・フィルタなど一覧を充実させる機能（思想1「一覧を眺めさせない」に反するため）

## 決めてほしいこと

なし（フェーズ4までの判断はすべて決定済み）

決定済み：並び替えの順序と空き時間の選択肢（15 / 30 / 45 / 60 / 90分）は案どおり（フェーズ1で実装）。冬眠までの日数は14日（フェーズ2で実装）。「始める」は集中画面、「今はやらない」は1時間、1行追加の既定は30分（フェーズ4で実装）
